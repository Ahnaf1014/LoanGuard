# LoanGuard engineering review

Review date: 2026-08-08

## Outcome

The implemented application is coherent and suitable for continued local/academic
development. The reviewed pages, database connection, schema invariants, and
editor workflow are operational. It is not ready for untrusted production users
because authentication, authorization, and audit logging are not implemented.

## Remediated in this review

- Reproducible VS Code interpreter, debug, task, extension, encoding, and
  SQLTools configuration
- Removal of tracked `.env` credentials and generated bytecode without deleting
  the local environment
- Flask application factory and production-secret fail-fast behavior
- CSRF protection, secure-cookie options, CSP/security headers, and HTTPS HSTS
- Shared server-side form parsing, length/range validation, and role validation
- Guaranteed cursor/connection cleanup with commit/rollback scopes
- Manager attribution and decision timestamps for terminal application statuses
- Portable SQL scripts without a hard-coded provider database name
- Monetary, date, score, decision, and payment constraints
- Trigger coverage for payment insert/update/delete, overpayment rejection,
  funded-application protection, and approved-loan enforcement
- Consistent responsive forms and corrected Bootstrap/offcanvas sidebar styling
- Unit, health, rollback-only database integration, backup, migration, and web
  smoke tooling

## Remaining priorities

### Required before production

1. Implement staff authentication using strong password hashes and secure session
   rotation.
2. Enforce role-based authorization on every borrower, application, assessment,
   loan, and payment action.
3. Add immutable audit events for decisions and financial changes; current
   records can be edited without preserving their prior values.
4. Rotate any secret or database password that was ever committed. The file is
   no longer tracked, but Git history still contains earlier versions unless the
   owner deliberately rewrites repository history.

### Recommended next engineering work

- Add loan-origination and payment web modules with authorization and audit
  events.
- Add pagination, filtering, and indexed search before data volumes grow.
- Add CI for unit tests, formatting, linting, SQL validation, and dependency
  vulnerability scanning.
- Decide whether to vendor Bootstrap assets or add Subresource Integrity for CDN
  dependencies.
- Introduce versioned migrations for every future schema change; the current
  migration is intentionally a one-time baseline upgrade.
- Select and populate an explicit software license.
- If the “exactly one loan subtype” rule must be database-enforced, add a
  controlled loan-creation procedure or a different subtype model; independent
  subtype tables cannot express that XOR rule with ordinary foreign keys alone.
